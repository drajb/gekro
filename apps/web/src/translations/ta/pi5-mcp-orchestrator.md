என் மூன்று Raspberry Pi 5 (16GB + M.2 256GB) நோடுகளில் ஒன்றைத் தனிமைப்படுத்தினேன், அது மாஸ்டர் கட்டுப்பாட்டு நிரலால் (MCP) ஆளப்படும், நிதி ரீதியாகத் தனிமைப்படுத்தப்பட்ட AI ஒருங்கிணைப்பாளராகச் செயல்பட. இலக்கு, நான் அன்றாடம் பயன்படுத்தக்கூடிய திறன் மிக்க, பல்நோக்கு AI உதவியாளர் அமைப்பை உருவாக்குவது; தொடர் நிலைப் பராமரிப்பால் என் "Pro" அடுக்கு API பில் முற்றிலும் ஆவியாகாமல்.

இந்த அமைப்பிலுள்ள வொர்க்கர்கள் குறுகிய, ஒற்றை-நோக்கப் பின்னணிச் சேவைகள் அல்ல. அவர்கள் முழுமையாகச் செயல்படும் தனிப்பட்ட உதவியாளர்கள்: அமைப்புகளைச் சுறுசுறுப்பாகக் கண்காணிக்கிறார்கள், தன்னாட்சிப் பின்னணிப் பணிகளைச் செய்கிறார்கள், தனிப்பட்ட உற்பத்தித்திறன் கருவிகளுடன் இணைகிறார்கள், Telegram வழியாகக் கேள்விகளுக்குப் பதிலளிக்கிறார்கள். ஆயினும் இவ்வளவு திறன் கொண்ட உதவியாளர்களை இயக்க ஒரு பாதுகாப்பு தேவை. தீர்வு ஒரு ஆக்ரோஷமான வழிப்படுத்தல் உத்தி: சூழலை மேற்பார்வையிட ஒரு மைய MCP-ஐப் பயன்படுத்துவது, உண்மையான உதவியாளர்கள் கணக்கு-நிலைக் கடுமையான செலவு வரம்புகள் கொண்ட திரட்டி வழியாக டாக்கரைஸ் செய்த பின்னணிச் செயல்முறைகளாக இயங்குவது. Pi இனி பொது-நோக்க வீட்டு ஆய்வகம் அல்ல: அதை அர்ப்பணிக்கப்பட்ட, வலையமைக்கப்பட்ட OpenClaw கூடாக மாற்ற, மற்ற ஒவ்வொரு கொள்கலனும் நீக்கப்பட்டது.

## கட்டமைப்பு

அமைப்பு பிளவுபட்ட-மூளை, அடுக்குக் கட்டமைப்பில் இயங்குகிறது. வேரில் MCP அமர்ந்துள்ளது. ஒரே விலையுயர்ந்த மாடலை நிரலில் பதிப்பதற்குப் பதிலாக, MCP ஒரு `manifest.ai` திறனை உள்ளமைந்த திசைவியாகப் பயன்படுத்துகிறது. அது நிர்வாகப் பணியின் சிக்கலைத் தானாக மதிப்பிட்டு எந்த Gemini மாடலை அழைக்க வேண்டும் என்று முடிவுசெய்கிறது, அடிப்படைச் செயல்திறனுக்காக Gemini-யின் நேட்டிவ் தானியங்கி முறையை இயல்புநிலையாக வைத்துக்கொள்கிறது.

அதன் கீழ், அர்ப்பணிக்கப்பட்ட Docker பாலம் வலையமைப்பில் (`claw_net`) முற்றிலும் தனிமைப்படுத்தப்பட்டு, இரண்டு பணி-குறிப்பிட்ட வொர்க்கர்கள் அமர்ந்துள்ளனர். வொர்க்கர்கள் முன்பணம் செலுத்திய OpenRouter இணைப்பு வழியாகக் கனமான வேலையைச் செய்கின்றனர். MCP அவர்களின் பதிவுகளைக் கண்காணித்து, அவர்கள் தோல்வியடைந்தால் அவர்களின் உள்ளமைவுகளை மீண்டும் எழுதி, அவர்களின் கொள்கலன்களை மறுதொடக்கம் செய்கிறது.

## உருவாக்கம்

போர்ட் மோதல்களையும் CPU மேல்செலவையும் நீக்க, இந்த மாற்றத்துக்கு Pi 5-ஐ அழிக்க வேண்டியிருந்தது. வன்பொருள் இப்போது முழுக்க முழுக்க OpenClaw ஹோஸ்ட்.

முதலில் எனக்குத் தூய்மையான பலகை தேவைப்பட்டது. எந்தப் பேய்க் கொள்கலனும் நினைவகத்தை மெல்லாமல், என் வழிப்படுத்தல் அடுக்குகளுடன் மோதாமல் இருக்க, இருக்கும் உள்கட்டமைப்பை முழுமையாகச் சுத்தப்படுத்தினேன். பிறகு தனிமைப்படுத்தப்பட்ட வலையமைப்பை (`claw_net`) உருவாக்கினேன். Telegram API-க்கும் OpenRouter-க்கும் வொர்க்கர்களுக்கு வெளிச்செல்லும் இணையம் தேவை, ஆனால் அவர்களைத் தனித்த பாலம் வலையமைப்பில் தனிமைப்படுத்துவது அவர்களுக்கு உள்வரும் அணுகல் இல்லை என்பதையும் ஒருவர் போக்குவரத்தை மற்றவர் பார்க்க முடியாது என்பதையும் உறுதி செய்கிறது.

```bash
# Purge all non-essential containers and images
docker stop $(docker ps -aq)
docker rm $(docker ps -aq)
docker system prune -a --volumes -f

# Create the dedicated network for the swarm
docker network create --driver bridge claw_net
```

படிநிலையைப் பிரதிபலிக்க `/opt/openclaw`-இல் கோப்பு முறைமையை மறுசீரமைத்து, வொர்க்கர்களின் உள்ளமைவுக் கோப்புகளின் மீது MCP-க்கு முழுமையான பார்வையைக் கொடுத்தேன்.

```bash
mkdir -p /opt/openclaw/{mcp,workers/worker-01,workers/worker-02}
```

அடுத்து தனிமைப்படுத்தப்பட்ட வொர்க்கர்களை உள்ளமைத்தேன். அவர்களின் அங்கீகாரத்தை OpenRouter-க்குப் பூட்டி, நேரடியாகக் கணக்கு மட்டத்திலேயே கடுமையான மாதாந்திரச் செலவு வரம்பை அமல்படுத்தினேன். இது பின்புலத்தில் செலவு மீறுவதைக் கட்டுப்படுத்துகிறது: ஒரு சுழற்சி நிகழ்ந்தாலும் அதிகபட்ச சேதம் வெளிப்படையாக வரம்பிடப்பட்டு, எதிர்பாராத 500 டாலர் மாதப் பில்லிலிருந்து என்னைக் காக்கிறது. நடைமுறையில், முழுத் திறன் கொண்ட, அன்றாடப் பயன்பாட்டு இந்த AI உதவியாளர்களை இயக்க எனக்கு மாதம் 8 முதல் 15 டாலர் வரை யதார்த்தமாகச் செலவாகிறது. தன்னிச்சையான திறன் உச்சவரம்புகளைத் திணிப்பதற்குப் பதிலாக, அவர்களின் `maxOutputTokens`, `maxHistoryTurns` ஆகியவற்றை எண்ணிச் செய்யப்பட்ட செயல்திறன் அளவுத்திருத்த அளவுருக்களாக நான் சீரமைத்தேன். இந்த மதிப்புகள் ஒவ்வொரு வொர்க்கரின் பங்கின் தன்மைக்குப் பொருந்துகின்றன, அதாவது விரைவான பதில்களுக்கும் சிக்கலான செயல்களுக்கும் ஏற்பச் சூழல் சாளரங்களை மேம்படுத்துதல், கணக்கீட்டு மேல்செலவை வீணாக்காமல் அவர்கள் முழுமையாகச் செயல்படுவதை உறுதிசெய்தல்.

```bash
# Configure Worker 01
cd /opt/openclaw/workers/worker-01
openclaw onboard --auth-choice apiKey --token-provider openrouter --token "$OPENROUTER_API_KEY" --non-interactive
openclaw config set agents.defaults.model.primary "openrouter/deepseek/deepseek-chat"
openclaw config set agents.defaults.maxOutputTokens 250
openclaw config set agents.defaults.maxHistoryTurns 5

# Configure Worker 02
cd /opt/openclaw/workers/worker-02
openclaw onboard --auth-choice apiKey --token-provider openrouter --token "$OPENROUTER_API_KEY" --non-interactive
openclaw config set agents.defaults.model.primary "openrouter/deepseek/deepseek-chat"
openclaw config set agents.defaults.maxOutputTokens 600
openclaw config set agents.defaults.maxHistoryTurns 8
```

வொர்க்கர்களைத் தனிமைப்படுத்தப்பட்ட வலையமைப்புடன் இணைத்து இயக்கினேன். அவர்களின் அந்தந்த உள்ளமைவுக் கோப்பகங்களை நேரடியாகக் கொள்கலன்களுக்குள் ஏற்றுவதன் மூலம், ஒரு வொர்க்கர் தவறாக நடக்கத் தொடங்கினால் MCP பின்னர் தலையிட்டு Docker சாக்கெட் வழியாக அந்த உள்ளமைவுகளைப் படித்து, இயங்குநிலையில் மீண்டும் எழுத முடியும்.

```bash
docker run -d --name worker-01 \
  --network claw_net \
  -v /opt/openclaw/workers/worker-01:/app/config \
  openclaw/core:latest

docker run -d --name worker-02 \
  --network claw_net \
  -v /opt/openclaw/workers/worker-02:/app/config \
  openclaw/core:latest
```

இறுதியாக, மாஸ்டர் கட்டுப்பாட்டு நிரல். MCP-க்கு Google AI நற்சான்றுகள் தேவை, ஆனால் தேவையற்ற டோக்கன் எரிப்பைத் தடுக்க `manifest.ai` வழிப்படுத்தல் திறனை நடைமுறைப்படுத்தினேன். துணைச் செயல்முறைகளை நேரடியாக மேற்பார்வையிட, Docker சாக்கெட்டையும் வேர் `/opt/openclaw/workers` கோப்பகத்தையும் அதன் கொள்கலனுக்குள் ஏற்றினேன். ராஜ்ஜியத்தின் சாவிகள் உள்ள ஒரே கொள்கலன் MCP.

```bash
cd /opt/openclaw/mcp
openclaw onboard --auth-choice oauth --token-provider google --non-interactive

# Inject the manifest.ai router skill and set dynamic defaults
openclaw skill add manifest.ai/router
openclaw config set agents.defaults.model.primary "google/gemini-auto"
openclaw config set routing.strategy "manifest-dynamic"

docker run -d --name mcp \
  --network claw_net \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /opt/openclaw/workers:/supervised_workers \
  -v /opt/openclaw/mcp:/app/config \
  openclaw/core:latest
```

## சமரசங்கள்

LLM-இயக்கும் கொள்கலனுக்குள் `/var/run/docker.sock`-ஐ ஏற்றுவது உற்பத்திச் சூழலில் பேரழிவான பாதுகாப்பு ஆபத்து. MCP ப்ராம்ப்ட் உட்செலுத்துதல் தாக்குதலுக்கு ஆளானால், Pi-யின் Docker பின்னணிச் சேவையின் மீது அதற்கு வேர்-நிலைக் கட்டுப்பாடு உண்டு. Pi 5 பௌதீகமாகத் தனிமைப்படுத்தப்பட்டு இந்தச் சோதனைக்கு மட்டுமே அர்ப்பணிக்கப்பட்டிருப்பதால் இந்த ஆபத்தை ஏற்றுக்கொண்டேன், ஆனால் இது நிறுவனப் பயன்பாட்டுக்கான மாதிரி அல்ல.

கூடுதலாக, `manifest.ai` திசைவி புத்திசாலி, ஆனால் தவறற்றதல்ல. சிதைந்த API பேலோடால் Worker 02 பெரிய ஸ்டாக் ட்ரேஸை வீசியபோது, திசைவி அதை "சிக்கலான பிழைதிருத்தப் பணி" என்று சரியாகக் கண்டறிந்து, இலகுவான Flash மாறுபாட்டுக்குப் பதில் செயலாக்கத்தைக் கனமான காரணமறிதல் மாடலுக்கு உயர்த்தியது. ஒரு தீர்வை முன்மொழிவதற்கு முன் MCP பிழைப் பதிவைப் படிக்க 40,000 டோக்கன்களை விழுங்கியது. அது Worker 02-இன் வெளியீட்டு வடிவத்தை வெற்றிகரமாக மீண்டும் எழுதி கொள்கலனை மறுதொடக்கம் செய்தது, ஆனால் அந்த ஒற்றைப் பிழைதிருத்தச் செயல் தானியங்கி முறையின் சேமிப்பைத் தவிர்த்து, DeepSeek-இல் Worker 02-இன் முழுச் செயல்பாட்டு வாரத்தைவிட அதிகமாகச் செலவானது.

## நான் கற்றது

வழிப்படுத்தல் தர்க்கத்தை நடைமுறைப்படுத்துவதற்கு முன், Worker 01 உண்மையில் அமைதியாகத் தோல்வியடைந்தது. Telegram-இலிருந்து வந்த சிதைந்த JSON பேலோடை அதனால் பகுக்க முடியவில்லை, அங்கேயே தொங்கிக்கொண்டிருந்தது, API மீண்டும் மீண்டும் காலக்கெடு முடிந்துகொண்டிருக்க, Pi-யின் நினைவக வளங்களை அமைதியாக மென்றுகொண்டிருந்தது. இரண்டு நாட்கள் நான் அதைக் கவனிக்கவில்லை. அந்த அமைதியும், அது ஏற்படுத்தக்கூடிய தொடர் தோல்வியுமே என்னை முதலில் MCP-ஐ உருவாக்கத் தூண்டியது.

அமைப்பு தற்போது நான் கைமுறையாக MCP-யிடம் வொர்க்கர்களைச் சரிபார்க்கச் சொல்வதைச் சார்ந்துள்ளது, இது அரைகுறை நடவடிக்கை. கட்டமைப்பின் தர்க்கரீதியான முடிவு, ஆய்வகத்தில் என் அடுத்த திட்டம், தொடர் இதயத்துடிப்புக் கண்காணிப்பியை நிறுவுவது. வொர்க்கர்களின் ஆரோக்கியச் சோதனைகளை Pi-யிலுள்ள இலகுவான உள்ளூர் வெக்டர் ஸ்டோருக்குள் குழாய் வழியாகச் செலுத்துவதன் மூலம், MCP தானாகவே வரலாற்றுச் செயலிழப்புத் தரவை வினவி, தோல்வி தொடராகப் பரவுவதற்கு *முன்பே* வொர்க்கர்களின் DeepSeek வெப்பநிலையை அல்லது டோக்கன் வரம்புகளை முன்கூட்டியே சரிசெய்ய முடியும்.

சிக்கலான AI அமைப்புகளை இயக்க மிகப்பெரிய, ஒற்றைக்கல் கிளவுட் உள்கட்டமைப்பு தேவையில்லை என்பதை இந்தச் சோதனை நிரூபித்தது. கட்டமைப்பை ஒற்றை Raspberry Pi 5-இன் பௌதீக வரம்புகளுக்குள்ளும் 8–15 டாலர் மாதாந்திரச் செலவு வரம்பின் நிதி வரம்புக்குள்ளும் தள்ளியதால், விளைவு சமரசம் செய்யப்பட்ட அல்லது கட்டுப்படுத்தப்பட்ட மணல்பெட்டியாக இல்லை. அந்தக் கட்டுப்பாடுகள்தான் உண்மையில் மேலும் ஒழுக்கமான, மிகத் திறன் கொண்ட ஒருங்கிணைப்பு அமைப்பை வடிவமைத்தன. இன்று இவை வெறும் குறுகிய ஸ்கிரிப்ட்கள் அல்ல; என் பணிப்பாய்வுகளைச் சுறுசுறுப்பாக நிர்வகிக்கும், உண்மையிலேயே பயனுள்ள, அன்றாடப் பயன்பாட்டு AI தனிப்பட்ட உதவியாளர்கள். ஆய்வகம் இறுதியாகப் புத்திசாலித்தனமாக இயங்குகிறது, உதவியாளர்கள் முழுமையாக விடுவிக்கப்பட்டுள்ளனர், என் பில்லிங் பக்கம் இறுதியாகச் சுவாரசியமற்றது.
