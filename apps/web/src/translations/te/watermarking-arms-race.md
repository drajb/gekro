## ఇన్‌స్పెక్టర్ నిర్మించడం

అందుకే తాను తనిఖీ చేయగలిగినదాన్ని మాత్రమే చెప్పే వెర్షన్‌ను నిర్మించాను.

C2PA వైపు అత్యధిక కోడ్ పట్టింది. Content Credentials మానిఫెస్ట్ JUMBF బాక్స్‌లో ఉంటుంది, ఆ బాక్స్ ఎక్కడ పడుతుందనేది కంటైనర్‌పై ఆధారపడుతుంది. PNG దాన్ని `caBX` చంక్‌లో ఉంచుతుంది, JPEG దాన్ని APP11 సెగ్మెంట్‌లో మోస్తుంది, SVG దాన్ని XML మెటాడేటాలో ఉంచుతుంది. దాన్ని కనుగొనడం అంటే ముడి బైట్లలో ఆ మార్కర్ల కోసం స్కాన్ చేయడం:

```ts
const scanC2PA = (buf: ArrayBuffer) => {
  const bytes = new Uint8Array(buf);

  const find = (needle: string): boolean => {
    const n = needle.length;
    const limit = bytes.length - n;
    for (let i = 0; i <= limit; i++) {
      let ok = true;
      for (let j = 0; j < n; j++) {
        if (bytes[i + j] !== needle.charCodeAt(j)) { ok = false; break; }
      }
      if (ok) return true;
    }
    return false;
  };

  const isPng = bytes[0] === 0x89 &&
    String.fromCharCode(bytes[1], bytes[2], bytes[3]) === 'PNG';

  const hasJumbf  = find('jumb') || find('jumd');
  const hasC2pa   = find('c2pa');
  const hasPngBox = isPng && find('caBX');

  return { found: hasC2pa || hasPngBox, hasJumbf, isPng };
};
```

అది ఒక మానిఫెస్ట్‌ను కనుగొంటుంది. దాన్ని ధృవీకరించదు. ధృవీకరణ అంటే సర్టిఫికెట్ చైన్, క్రిప్టోగ్రాఫిక్ సంతకాన్ని తనిఖీ చేయడం, దాన్ని బ్రౌజర్ ట్యాబ్‌లో చేత్తో రాసి అధికారికంగా చూపించను. టూల్ ఆ మాట చెప్పి అధికారిక వెరిఫైయర్ వైపు చూపుతుంది.

స్కాన్‌కు ఒక వైఫల్య తీరు ఉంది, దాన్ని దాచకుండా పేరు పెట్టి చెప్పాలి. ముడి బైట్లలో నాలుగు అక్షరాల మార్కర్ కోసం వెతికితే తప్పుడు పాజిటివ్ రావచ్చు, ఎందుకంటే కుదించిన ఇమేజ్ డేటా లోపల `c2pa` బైట్లు రావడాన్ని ఏదీ ఆపదు. అయినా నేను దాన్ని ఉంచాను. మూడు ఫార్మాట్లలో కంటైనర్ నిర్మాణాన్ని సరిగ్గా పార్స్ చేయడం, "ఇక్కడ ఏదో ఉంది, వేరే చోట ధృవీకరించుకోండి" అనేదే మొత్తం వాదన అయిన టూల్‌కు చాలా శ్రమ. ఇది ఒక స్మోక్ అలారం, లేబుల్ కూడా అదే చెబుతుంది. ఎప్పుడైనా ఇది చాలకపోతే, పరిష్కారం నిజమైన బాక్స్ పార్సింగ్.

టెక్స్ట్ వైపు నా దాచిన-టెక్స్ట్ ఇన్‌స్పెక్టర్ కోడ్‌పాయింట్ స్కానర్‌ను మళ్లీ వాడుతుంది: జీరో-విడ్త్ అక్షరాలు, పూర్తి ASCII సందేశాలను కనిపించకుండా రవాణా చేయగల Unicode Tag బ్లాక్, bidi నియంత్రణలు, వేరియేషన్ సెలెక్టర్లు. ఇవన్నీ గుర్తించదగినవి, గుర్తు పెట్టదగినవి.

కష్టతరమైన భాగం కోడ్ కాదు. అది ఒకే తీర్పు పదాలు. టూల్‌లో "గణాంక వాటర్‌మార్క్ (Claude, SynthID-Text)" అనే సంకేతం ఉంది, దాని శాశ్వత స్థితి `not checkable`, వివరణతో కలిపి. విడుదల చేసే ముందు దీని మీద చాలా సేపు ఆలోచించాను, ఎందుకంటే "నాకు తెలియదు" అని జవాబిచ్చే టూల్ చెడిపోయినట్టు కనిపిస్తుంది.

ఈ ఫలితాలు ఎలా వాడబడతాయి అనేదాని వల్ల ఇది ముఖ్యం. ఎవరో ఒక పేరాను చెకర్‌లో వేసి అవుట్‌పుట్‌ను క్రమశిక్షణ సమావేశానికి తీసుకెళ్తారు. అందుకే టూల్ నాలుగు హెచ్చరికలతో మొదలవుతుంది. మొదటి రెండు Anthropic సొంత వైఖరి, మిగిలిన రెండు నేను నిర్మించినదాని పరిమితుల గురించి నావి:

- గుర్తు లేకపోవడం మానవ రచనకు రుజువు కాదు. భారీ ఎడిటింగ్, పారాఫ్రేజింగ్, అనువాదం, ఇతర రచనతో కలపడం గుర్తులను గుర్తించలేని స్థితులుగా Anthropic జాబితా చేస్తుంది.
- గుర్తు ఉండటం కూడా రచయిత అని రుజువు కాదు. కంటెంట్ ఆ మోడల్ ద్వారా ప్రాసెస్ అయి ఉండవచ్చని అది సూచిస్తుంది, ఎవరు రాశారో, మనిషి ఎంత మార్చారో కాదు.
- C2PA ఉనికి C2PA ధృవీకరణ కాదు. ఈ టూల్ ఒక మానిఫెస్ట్‌ను కనుగొంటుంది, సంతకాన్ని లేదా జారీచేసినవారిని ధ్రువీకరించదు.
- మెటాడేటా పెళుసైనది. స్క్రీన్‌షాట్లు, మళ్లీ సేవ్ చేయడం, చాలా ప్లాట్‌ఫాం అప్‌లోడ్లు దాన్ని తొలగిస్తాయి, కాబట్టి డౌన్‌లోడ్ చేసిన ఫైల్‌పై శుభ్రమైన ఫలితం అసలు గురించి చాలా తక్కువ చెబుతుంది.

## ఒక పత్రానికి ఇద్దరు రచయితలు ఉంటే ఏమవుతుంది

పైవన్నీ ప్రతి పత్రానికి ఒక రచయిత అని ఊహిస్తాయి. దాదాపు దేనికీ ఒకరు ఉండరు. ప్రజలు ఒక చాట్‌బాట్‌లో డ్రాఫ్ట్ చేస్తారు, ఒక విభాగాన్ని మరొకదానిలో తిరగరాస్తారు, ఆ వారం ఏది చవకో దానికి OpenRouter ద్వారా రూట్ చేస్తారు, మధ్యలో చేత్తో ఎడిట్ చేస్తారు. ఇది అరుదైన తప్పించుకునే టెక్నిక్ కాదు, ఇప్పుడు ప్రజలు పనిచేసే తీరు ఇదే.

Anthropic ఇప్పటికే దీన్ని గుర్తిస్తుంది. గుర్తు గుర్తించలేని స్థితుల వారి జాబితాలో "భారీగా ఎడిట్ చేసిన, పారాఫ్రేజ్ చేసిన, అనువదించిన లేదా ఇతర రచనతో కలిపిన" టెక్స్ట్ ఉంది. వారు దీన్ని హెచ్చరికగా చెప్పి అక్కడే వదిలేస్తారు. యంత్రాంగం ఇదిగో, ఎందుకంటే ప్రభావం పరిమాణం నన్ను ఆశ్చర్యపరిచింది.

గ్రీన్-లిస్ట్ గుర్తింపు టోకెన్ లెక్కలపై ఒక z-పరీక్ష. ఇది ప్రచురితమైన గ్రీన్-లిస్ట్ నిర్మాణం, ఉదాహరణ పారామీటర్లతో. ఇది Anthropic పథకం కాదు, అది ప్రచురితం కాలేదు. ఫలితపు ఆకారం వర్తిస్తుంది, నిర్దిష్ట సంఖ్యలు కావు.

```
z = (greens - γT) / sqrt(T · γ(1-γ))
```

ఒక పత్రంలో `T` టోకెన్లు ఉన్నాయనుకోండి, వాటిలో `W` మాత్రమే యంత్రం రాసినవి, ప్రతిదీ గ్రీన్ రేటును `ε` పెంచుతుంది. మానవ టోకెన్లు ప్రాథమిక రేటు `γ` వద్ద గ్రీన్లు ఇస్తాయి, కాబట్టి ఆశించిన గ్రీన్ లెక్క `Tγ + Wε`, మొత్తం పత్రపు గణాంకం ఇలా అవుతుంది:

```
z_whole = W·ε / sqrt(T · γ(1-γ))
```

ఇప్పుడు యంత్రం రాసిన భాగాన్ని మాత్రమే స్కోర్ చేయండి:

```
z_span  = ε·sqrt(W) / sqrt(γ(1-γ))
```

ఒకదాన్ని మరొకదానితో భాగిస్తే అంతా కొట్టుకుపోయి ఒకే సంఖ్య మిగులుతుంది:

```
z_whole / z_span = sqrt(W/T) = sqrt(f)
```

మొత్తం పత్రాన్ని స్కోర్ చేస్తే మీ గుర్తింపు శక్తిలో యంత్రం రాసిన భాగపు వర్గమూలం మాత్రమే మిగులుతుంది. `f = 0.1` వద్ద అది 32%. ఉదాహరణ విలువలుగా `γ = 0.5`, గ్రీన్ రేటు పెరుగుదల `ε = 0.25` తీసుకుంటే, 300 టోకెన్ల యంత్రం రాసిన భాగం ఒంటరిగా `z = 8.66` స్కోర్ చేసి అపారమైన నమ్మకంతో గుర్తు పెట్టబడుతుంది. అదే భాగాన్ని 3,000 టోకెన్ల పత్రంలో వేస్తే మొత్తం పత్రపు స్కోర్ `z = 2.74`కి పడిపోతుంది, ఏ సహేతుక హద్దు కంటే కూడా తక్కువ. వాటర్‌మార్క్ మారలేదు. డిటెక్టర్ తప్పు ప్రమాణాన్ని కొలిచింది.

కాబట్టి మోడల్స్ కలపడం వాటర్‌మార్క్‌పై దాడి చేయదు. అది డిటెక్టర్ విండో ఎంపికపై దాడి చేస్తుంది.

పరిష్కారం టెక్స్ట్ పైన ఒక విండోను జరుపుతూ గరిష్ట స్కోర్ తీసుకోవడం, SynthID-Text పేపర్‌లోని WinMax ఆలోచన దాదాపు ఇదే. ఇది పనిచేస్తుంది, దానికి ఖరీదు కూడా ఉంది. వందలాది అతివ్యాప్తి విండోలను స్కోర్ చేయడం అంటే ఒకే పత్రంపై వందలాది పరికల్పన పరీక్షలు నడపడం, కాబట్టి బహు-పోలిక సవరణ కావాలి, అది హద్దును పైకి నెడుతుంది, అది చిన్న భాగాలను మళ్లీ దాని కిందికి నెడుతుంది. మీరు పలుచబడే సమస్యను తప్పుడు పాజిటివ్ సమస్యతో మార్చుకుంటారు, ఆ డయల్‌ను ఎలా సెట్ చేసినా రెండూ తప్పవు.

విండోయింగ్ కూడా ఒక వెండర్ గుర్తును మాత్రమే స్థానీకరిస్తుంది, ఎందుకంటే ప్రతి ప్రొవైడర్ తన సూడో-రాండమ్ ఫంక్షన్‌ను తన కీతో నడుపుతాడు:

```
for each vendor key K:          # Anthropic, Google, OpenAI, ...
    for each window w in text:  # all of these need FPR correction together
        score(w, K)
```

ముగ్గురు వెండర్లు అంటే మూడు డిటెక్టర్లు, మూడు API రౌండ్-ట్రిప్‌లు, మూడు నమ్మక సంబంధాలు. ఫెడరేటెడ్ వెర్షన్ ఎవరూ ఇవ్వరు, Anthropic దైతే ఇంకా పబ్లిక్ కాదు.

ఆ తర్వాత పై వాటిలో చాలావరకు అకడమిక్‌గా చేసే రంధ్రం ఉంది. వాటర్‌మార్కింగ్‌కు ఇన్ఫరెన్స్ నడిపేవారు శాంప్లింగ్ దశను వంచాలి. అది సర్వింగ్ స్టాక్ లక్షణం, టెక్స్ట్‌ది కాదు. కాబట్టి:

OpenRouter రూటింగ్ ద్వారా వాటర్‌మార్క్‌ను ఓడించదు. అది గుర్తు ఎప్పుడూ వర్తింపజేయని లేన్‌ను అందిస్తుంది, ఆ లేన్ ఒక కాన్ఫిగ్ స్ట్రింగ్ దూరంలో ఉంది. కాబట్టి ఈ వ్యవస్థ యాజమాన్య ఫ్రాంటియర్ API లను మాత్రమే కవర్ చేస్తుంది, మరేమీ కాదు. ఓపెన్ వెయిట్స్ చాలా టెక్స్ట్ పనులకు ఇప్పటికే సరిపడా మంచివి, వ్యవస్థ బయట ఉన్నాయి. దీన్ని తప్పించుకోవాలనుకునేవారు మోడల్ పేరు మారుస్తారు.

పలుచబడే ప్రభావాన్ని ఇన్‌స్పెక్టర్‌లో మూడో ట్యాబ్‌గా నిర్మించాను. అది ఏ టెక్స్ట్‌నూ విశ్లేషించదు, ఏదీ గుర్తించదు. అది z-పరీక్ష గణితాన్ని నడిపి, యంత్రం రాసిన భాగాన్ని మార్చినప్పుడు రెండు స్కోర్లు ఎలా విడిపోతాయో గీస్తుంది.

## నేను ఏం తప్పు చేశాను

వాటర్‌మార్క్ మన్నిక అంటే ఎడిట్లను తట్టుకోవడం అని నేను ఊహించాను. అది పారాఫ్రేజ్‌ను తట్టుకోవడం, అది చాలా కష్టం, ఎందుకంటే పారాఫ్రేజ్ టోకెన్ ఎంపికలను మళ్లీ శాంపిల్ చేస్తుంది, సంకేతం ఉండేది అక్కడే. నా మొదటి ప్రణాళిక నమ్మకం శాతంతో ఉన్న చెకర్, ఎందుకంటే ప్రజలు ఆశించేది అదే, ర్యాంక్ అయ్యేది అదే. దాన్ని చంపేశాను. నేను ఇచ్చే ఏ సంఖ్య అయినా వేరే లేబుల్ కింద ఒక సాధారణ AI-టెక్స్ట్ క్లాసిఫైయర్ అయి ఉండేది, వాటికి నమోదైన తప్పుడు పాజిటివ్ సమస్యలున్నాయి, ముఖ్యంగా ఇంగ్లీష్ మాతృభాష కాని రచయితలకు వ్యతిరేకంగా.

కష్టమైన నిర్ణయం వాటర్‌మార్క్ రిమూవర్, నిజంగా ట్రాఫిక్ తెచ్చే పక్క ఉత్పత్తి. దాన్ని వదిలేశాను. అది వెల్లడి నిబద్ధతను తప్పించుకునే టూల్ అయ్యేది, ఎలాగూ పనిచేయదు కూడా. తొలగించడానికి అక్షరం లేదు, కాబట్టి తొలగింపు అంటే రచనను పాడుచేసేంత దూకుడైన పారాఫ్రేజ్, బ్రౌజర్ టూల్ మోడల్‌ను పంపకుండా పారాఫ్రేజ్ చేయలేదు. తర్వాత నాకు మిగిలిన విషయం, దీనితో పాటు నేను విడుదల చేసిన విరామచిహ్న సరిదిద్దే టూల్ జీరో-విడ్త్ అక్షరాలను తొలగిస్తుంది, అది నా సొంత డ్రాఫ్ట్‌ల కోసం నేను కోరుకున్న శుభ్రత. అదే రెజెక్స్, వేరే ఉత్పత్తి. గీత కోడ్‌లో లేదు, టూల్ దేనికోసమో పేజీ ఏం చెబుతుందనే దానిలో ఉంది.

## ఇది ఎటు వెళ్తుంది

వెండర్ మాత్రమే ధృవీకరించగల మూల సంకేతం ఇంకా ప్రజా మూల రుజువు కాదు. కానీ sqrt(f) ఫలితం "ఆయుధ పోటీ కొనసాగుతుంది" కంటే మరింత నిర్దిష్టమైన దాని వైపు చూపుతుంది. కంటెంట్ ఆధారిత ఫోరెన్సిక్స్ మాత్రమే ప్రజలు నిజంగా అడిగే ప్రశ్నకు జవాబు చెప్పలేదు. టెక్స్ట్ సృష్టించబడిందా లేదా కాదు, ఏ భాగాలు, ఎవరిచేత, మనిషి ఎంత మార్చాడు. మన దగ్గరున్న ప్రతి యంత్రాంగం నిజమైన పత్రాలు ఉండే చోటే, అనేక రచయితలు, సుదీర్ఘ ఎడిట్ చరిత్ర ఉన్న ఫైళ్లలోనే క్షీణిస్తుంది. కాబట్టి ఉపయోగకరమైన అడుగు బహుశా టెక్స్ట్‌ను ప్రశ్నించడం మానేసి పరిసరాన్ని రికార్డ్ చేయడం మొదలుపెట్టడం. ఎడిటర్ రివిజన్ చరిత్ర, కమిట్ టైమ్‌లైన్‌లు, సంతకం చేసిన ఎడిట్ చైన్లు పూర్తయిన కళాఖండంపై ఏ గణాంక పరీక్ష కంటే చాలా నమ్మకంగా రచయితృత్వాన్ని ఇప్పటికే పట్టుకుంటాయి, C2PA అసర్షన్ మోడల్ ఇదే రకమైన పొరలుగా, అనేక పాత్రధారులున్న మూల రుజువును లక్ష్యంగా చేసుకుంటుంది. వాటర్‌మార్క్ అసలు పని శీర్షికలు సూచించిన దానికంటే ఇరుకైనది. ఇది ఎవరూ దాచడానికి ప్రయత్నించని యంత్ర టెక్స్ట్ కోసం డిఫాల్ట్-ఆన్ వెల్లడి, ప్రతికూల సందర్భాలు ఎప్పుడూ ఉండాల్సిన చోటే నిర్వహించబడతాయి, పత్రం ఎలా తయారైందో రికార్డ్ చేసే టూల్స్‌లో.
